The Doctor tells you why a site is down.

- `paddock doctor [site]`, **Check a Site…** in the menu and a Check button on each Settings → Sites row all run the same checklist: the daemon, ports 80 and 443, the port helper, the `.resolver` entry, DNS, Caddy, PHP and PHP-FPM, the site folder, certificate trust, the site's actual HTTP answer and the newest error in its log.
- Each failed row with a remedy names the one command that fixes it. One cause produces one red row; checks that a failed step makes meaningless are skipped, not repeated.
- The HTTP check looks at the site the way a browser does, certificate trust included, on the port Paddock actually serves.
- `paddock mcp` gains a read-only `doctor` tool, so an agent can read the failed rows before suggesting a fix.
- `paddock env <service> [site]` and **Write to .env…** in Settings → Services write a service's keys into a site's `.env`, updating them in place and leaving every other line untouched. The file must already exist, must not be a symlink and must be UTF-8; keys are named in the result, values never are.
